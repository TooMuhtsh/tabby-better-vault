Contexte & invariants

Dernière revue : 2026-07-26

Ce projet n'a pas encore de code — cette page ne contient donc pas de pièges propres découverts en implémentant (elle se remplira au fil du développement, comme celle du projet frère). Elle liste pour l'instant les pièges hérités, hautement probables vu que ce plugin partage exactement la même stack (Tabby, Angular 15, Electron, TypeScript, webpack) que tabby-better-sidebar — à vérifier/confirmer dès le scaffold, pas à redécouvrir de zéro.

Identité du projet

  • Nom prévu : tabby-better-vault (npm/GitHub), à créer.
  • Objectif unique : déverrouiller automatiquement le coffre-fort Tabby (mot de passe maître) au démarrage, en déléguant le chiffrement à l'OS plutôt qu'en stockant le secret en clair.
  • Relation avec tabby-better-sidebar : projet frère, pas une dépendance obligatoire — better-sidebar peut détecter la présence de ce plugin et exposer un lien vers ses réglages si installé, mais fonctionne normalement sans lui (interfaçage optionnel, voir ROADMAP.html).

Pièges hérités du projet frère — à anticiper dès le scaffold

Détail complet de chacun dans l'AI-CONTEXT.html de tabby-better-sidebar — pas dupliqué ici pour éviter que les deux copies divergent avec le temps. Seul le résumé et le pourquoi ça s'applique probablement ici aussi.

Environnement & build

  • Piège #1 — TABBY_PLUGINS cassé sur Windows (bug Tabby, pas du plugin) : utiliser une jonction NTFS dans %APPDATA%\tabby\plugins\node_modules\, jamais cette variable d'env.
  • Piège #2 — package.json doit toujours avoir un champ author (même vide), sinon échec silencieux de la découverte du plugin.
  • Piège #4 — mêmes contraintes de version probables pour matcher Angular 15 (peer dep de tabby-core) : typescript@^4.9, pug@^2.0, @types/node@^18.19, @ng-bootstrap/ng-bootstrap@^14 — à revérifier au moment du scaffold (la version d'Angular ciblée par Tabby a pu changer depuis).
  • Piège #5 — si ce plugin dépend de tabby-ssh (peu probable, le Vault n'a a priori rien à voir avec SSH) : npm install --ignore-scripts à cause d'un postinstall natif inutile.

Composants Angular dans un plugin tiers

  • Piège #3 — templateUrl/styleUrls ne marchent pas pour un plugin tiers ; utiliser template: require('./x.pug') et un import SCSS en side-effect. S'applique à tout composant Angular ajouté par ce plugin (ex. panneau de réglages).

Vérifier une classe/API Tabby avant de s'y fier

Le point le plus important pour ce projet

Ce plugin dépend entièrement d'une classe non confirmée exportée : VaultService (ou équivalent). Voir le garde-fou bloquant dans README.html.

  • Piège #6 — les typings npm de tabby-core sont probablement en retard sur l'app installée, comme pour ProfilesService.
  • Piège #13 — @hidden ne veut pas dire "non exporté" : toujours vérifier les DEUX niveaux (typings/index.d.ts ET le bloc d'export webpack réel de dist/index.js compilé) avant de conclure qu'une classe est inutilisable.
  • Piège #17 — même si une classe est exportée dans le bundle réel, les typings npm peuvent nommer ses champs différemment de l'implémentation réelle (vu sur EditProfileModalComponent) — vérifier les noms de champs dans le bundle compilé, pas seulement dans les typings.

Debug & workflow de dev

  • Piège #8 — Tabby.exe --debug --remote-debugging-port=9333 pour le Chrome DevTools Protocol. Après toute modification du plugin, tuer et relancer tout le process Tabby.exe (pas un simple reload).

Git & GitHub

  • Pièges #9/#10/#11 — vérifier le compte GitHub actif avant gh auth login, configurer l'identité de commit localement au dépôt (pas --global), et la réécriture d'historique (git filter-branch) doit être lancée par l'utilisateur lui-même via le préfixe !.

Invariant propre à ce projet — sécurité du secret

Non négociable, à respecter dès la première implémentation

La variable JS contenant le mot de passe maître déchiffré en clair doit être immédiatement écrasée (= null) dès que l'injection dans le moteur de Tabby est validée — voir détail complet dans ROADMAP.html. C'est la seule règle de ce projet qui n'est pas négociable même en phase d'exploration/prototype : un secret en clair ne doit jamais traîner en mémoire plus longtemps que nécessaire.
